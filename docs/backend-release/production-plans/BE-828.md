# BE-828 — Runtime còn được hỗ trợ
Baseline: PROD-2026-09-22-v1. Plan revision: 1 (2026-09-22).
Implementation status: TODO. Plan đã có; chưa triển khai/chưa VERIFIED.
Owner: backend developer; review nghiệp vụ với app/admin developer liên quan.
P0; depends: BE-800; requirement: BR-16.

## 1. Mục tiêu và hiện trạng
Stack .NET8; gần cuối vòng hỗ trợ theo nguồn Microsoft.
Kết quả cần đạt: Release runtime còn support; nếu giữ .NET8 trước EOL có owner/deadline upgrade trước EOL. Không launch trên runtime hết hỗ trợ.
Đây là mốc khảo sát, phải xác minh lại working tree/route/schema trước code; không tự làm lại phần đã đạt.

## 2. Scope
**In:** Lập kế hoạch upgrade LTS được hỗ trợ; thử SDK/EF/Npgsql/tooling/images/CI và regression; không đổi stack trong docs task.
**Out:** Không đổi database/provider/framework architecture, chọn preview runtime hoặc tự chạy incompatible migration.
Không tự mở rộng scope để hoàn tất một dependency chưa được giao; ghi partial blocker và triển khai phần độc lập.

## 3. Contract và dữ liệu
- API: Wire behavior must remain stable; document any framework serializer/auth changes as contract diff, not invisible upgrade.
- Schema/consistency: SDK/TFM/EF/Npgsql/tool versions/images lockfile consistent; no schema change unless EF actual model diff requires reviewed migration.
- Trước sửa: tìm symbol/controller/config/migration thực tế bằng rg, ghi đường dẫn thực tế trong evidence. Không tạo type/table trùng chỉ vì plan dùng tên khái niệm.
- Proposed route/field phải cập nhật OpenAPI, auth matrix, sample success/error và generated client trước tích hợp; additions ở đây không chứng minh API đã tồn tại.
- Nếu không cần migration, ghi N/A và lý do. Nếu cần: inventory/backfill precheck → expand → verify → cutover; Up/Down rõ, destructive step có recovery riêng.

## 4. Trình tự triển khai
1. Verify official runtime support dates at execution, inventory SDK/images/NuGet/tools compatibility and choose supported LTS target.
2. Prototype upgrade branch/isolated worktree when needed; build all projects/bundle/CI; review breaking auth/JSON/EF changes.
3. Run unit/integration/contract/perf smoke and container migration from existing DB; fix warnings introduced by upgrade.
4. Record support deadline/patch cadence/rollback image and operator launch decision; keeping8 requires upgrade completed before EOL.
5. Bổ sung tests bên dưới, chạy kiểm tra phù hợp source mới, cập nhật evidence và FE handoff. Không đánh VERIFIED khi integration còn pending.

## 5. Luồng lỗi, retry và kiểm thử
Token validation/Identity hashing, JSON casing/time serialization, PostgreSQL migrations/provider SQL, EF bundle runtime architecture, generated clients regression.
- Kiểm success + validation + unauthenticated + forbidden/not-owned + conflict chỉ khi áp dụng cho operation.
- DB constraints/transactions/concurrency phải chạy PostgreSQL thật, không chứng minh bằng mock/InMemory.
- Tách provider stub dành tests khỏi bằng chứng sandbox/live. Khi thiếu credentials chỉ phần external bị blocked.
- Không cố định tổng số tests; ghi command, số passed/failed/skipped, source revision và environment.

## 6. Bảo mật và quan sát
Authorization ở Application, allowlist input/output, không tin actor/role từ client.
Không log credentials, raw tokens, health/chat hoặc provider payload thô; dùng traceId/resource ID được phép.
Ghi signal vận hành của phần thay đổi (error/retry/latency/queue theo tính chất task), tránh metric label chứa PII/high cardinality.

## 7. Hai frontend và rollout
No UI changes; generated types diff expected empty unless reviewed explicit contract change.
Trước enable: backend compatible + contract hash/fixtures + client adapter/tests; không fallback mock trong production.
Nếu không đổi client contract, ghi explicit “no wire change” trong handoff.

## 8. Migration, failure recovery và rollback
If schema unchanged rollback previous supported image; if migrations applied use compatibility report. No launch on EOL runtime; isolate upgrade from business schema refactor.
Không tự deploy/migrate production hoặc tạo tài nguyên trả phí. Recovery sau dữ liệu thật phải bảo toàn ledger/history và được operator duyệt.

## 9. Chia commit dự kiến
- build(runtime): align the supported backend toolchain [BE-828]
- test(runtime): verify upgrade compatibility [BE-828]
Đây là message dự kiến, không phải approval commit. Ranh giới có thể điều chỉnh để mỗi commit build được và có nghĩa; không commit interface rỗng chỉ cho đủ số.
Tuân thủ rule hỏi duyệt message trước commit, không attribution, không commit thay đổi người khác.
