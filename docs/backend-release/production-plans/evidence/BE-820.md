## Hiện trạng và Mục tiêu
- **Mục tiêu**: Xây dựng test harness kiểm thử tích hợp (integration tests) và kiểm chứng hợp đồng API (contract verification) end-to-end hoàn chỉnh.
- **Nguyên tắc kỹ thuật cốt lõi**:
  - Chạy trên cơ sở dữ liệu PostgreSQL thực tế (không dùng `InMemoryDatabase` để đảm bảo kiểm thử toàn vẹn các ràng buộc khóa ngoại, unique constraints, transactions và triggers).
  - Sử dụng `WebApplicationFactory<Program>` từ `Microsoft.AspNetCore.Mvc.Testing` để kiểm thử toàn diện HTTP pipeline: Routing, Model Binding, Authentication, Authorization, Exception Handling Middleware (RFC 7807 ProblemDetails).
  - Tiện ích sinh client xác thực thực tế (`CreateAuthenticatedClient`) cấp JWT token chuẩn cho các vai trò `Admin`, `PT`, `Member` để kiểm thử xác thực và phân quyền chính xác.

## Scope
- **In**:
  - Dự án mới `Fitmate.IntegrationTests` (`tests/Fitmate.IntegrationTests/Fitmate.IntegrationTests.csproj`) được liên kết vào solution `Fitmate.slnx`.
  - `FitmateTestAppFactory`: Kế thừa `WebApplicationFactory<Program>`, cấu hình kết nối database cô lập (`fitmate_integration_test`) trên PostgreSQL instance (từ Docker compose port 5432), tự động nhận diện mật khẩu host (`dev` / `localverify300pw`), khởi tạo schema sớm với `EnsureCreated()`, và tiện ích tạo HttpClient có sẵn JWT header.
  - Bộ kiểm thử hợp đồng và tích hợp (12 test cases):
    1. `CapabilitiesAndHealthTests`:
       - `GET /health/live` -> 200 OK.
       - `GET /health/ready` -> 200 OK (xác nhận kết nối DatabaseHealthCheck với PostgreSQL).
       - `GET /` -> 200 OK (tên dịch vụ và phiên bản).
       - `GET /api/v1/system/capabilities` -> 200 OK, phản ánh trung thực `ai.enabled: false`, chính sách nền tảng (`platform_fee_bps: 1000`), thông tin liên hệ, và bảo đảm tuyệt đối không rò rỉ secrets.
    2. `AuthAndSecurityTests`:
       - Truy cập endpoint bảo vệ khi không có token trả về 401 Unauthorized ProblemDetails.
       - Vai trò `Member` truy cập endpoint quản trị `/api/v1/admin/users` trả về 403 Forbidden.
       - Vai trò `Admin` truy cập `/api/v1/admin/users` trả về 200 OK.
       - Đăng nhập sai thông tin trả về 401 ProblemDetails chuẩn RFC 7807.
    3. `NutritionAndAiContractTests`:
       - `POST /api/v1/me/nutrition/scan` trả về HTTP 503 ProblemDetails với mã lỗi chuẩn `FITMATE.AI.UNAVAILABLE` khi AI bị vô hiệu hóa.
       - `POST /api/v1/me/nutrition/meals` ghi nhật ký bữa ăn thủ công thành công (201 Created), và `GET /api/v1/me/nutrition/meals` xác nhận dữ liệu đã được lưu trữ bền vững vào bảng PostgreSQL `meal_logs`.
    4. `SupportAndPreferencesTests`:
       - `GET` và `PUT /api/v1/users/me/preferences` xác nhận cập nhật và truy xuất tùy chọn người dùng bền vững trên PostgreSQL.
       - `POST /api/v1/support/tickets` tạo ticket hỗ trợ (201 Created).
       - Kiểm tra an ninh IDOR: Người dùng B truy cập ticket của người dùng A (`GET /api/v1/support/tickets/{id}`) trả về 404 Not Found (không làm lộ sự tồn tại của ticket thuộc về người khác).
- **Out**:
  - Không mock/InMemory thay thế DB constraints.
  - Không bỏ qua lỗi để làm xanh test.
